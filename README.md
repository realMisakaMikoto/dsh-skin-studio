# dsh-skin-studio

Create, manage, and share portable skins for the DeepSeek Harness Web UI.

`dsh-skin-studio` keeps DSH's native light, dark, and system appearance behavior while layering a user-created skin over the official `--dsw-*` theme tokens. Each skin can include two editable color palettes, a main image or looping video background, media backgrounds for any visible component type, UI and code fonts, and safe advanced color-token overrides.

![Skin Studio editor](docs/screenshots/skin-editor.png)

## Install

```sh
dsh plugin --profile web add dsh-skin-studio
dsh web
```

Open **Settings -> General -> Custom skins**.

## Features

- A library of named skins with create, duplicate, edit, activate, delete, and restore-default actions.
- Six approachable color roles for both light and dark modes.
- A guided GUI editor for inputs, buttons, sidebars, messages, code, borders, and status colors.
- An all-token view covering runtime-exposed colors and the plugin's verified component-color allowlist.
- OKLCH-based counterpart generation, followed by independent editing.
- Live preview with Apply and Cancel boundaries.
- PNG, JPEG, WebP, MP4, or WebM backgrounds with per-mode background opacity, interface veil, and scrim controls. Videos are always muted and loop automatically.
- Background media uses centered cover cropping and follows the responsive main conversation area without painting behind the conversation list.
- The mouse-and-keyboard component picker can target any visible DSH component type—including sidebars, inputs, buttons, message bubbles, menus, and panels—and give each type its own image or muted looping video with per-mode opacity and scrim controls.
- Component videos play only while visible, use a bounded playback pool, and become still frames when the system requests reduced motion. Weak readability scrims require explicit confirmation.
- Optional WOFF2 UI and code fonts.
- Advanced editing is limited to DSH color tokens on the plugin's explicit allowlist.
- A brighter `Bright Studio` default skin alongside more opinionated examples.
- Versioned IndexedDB persistence, a lightweight active snapshot, and same-origin tab updates.
- Portable `.dshskin` ZIP packages containing `manifest.json` and verified local assets.
- Chinese and English UI.

## Package safety

Imports are fail-closed. A package must use the v3 schema, valid asset paths, declared sizes, matching MIME signatures, and SHA-256 hashes. Component targets are structured tag/role/class locators generated by the picker; arbitrary CSS selectors are never accepted. SVG, GIF, remote URLs, CSS, HTML, JavaScript, and path traversal are rejected. The package limit is 128 MB; an image may be up to 15 MB, a video up to 100 MB, and each font up to 5 MB. Existing v1 and v2 skins migrate automatically.

Low contrast is reported before Apply. It remains possible to apply a deliberately low-contrast skin after explicit confirmation.

## Development

```sh
pnpm install
pnpm check
pnpm pack
```

The package has a no-op Host half and a browser client bundle. Runtime state uses the official Theme and Slot APIs; no Host settings namespace or custom server route is required.

## Compatibility and limits

The tested baseline is `@deepseek-ai/dsh 0.1.0-rc.6`. Settings are local to the current browser origin. v3 does not provide cross-browser Host sync, an online marketplace, arbitrary CSS/JS, layout editing, or global radius editing.
